## 2024-05-15 - React.memo and Callback Stale Closures
**Learning:** Using `React.memo` with list components (like `BookCard`) where the parent passes inline arrow functions as callbacks defeats the purpose of memoization, as the arrow functions create new references on every render, causing child re-renders. Furthermore, attempting to optimize by using a custom comparison function that ignores callback changes can lead to stale closures if the callbacks capture outdated state (e.g., closing over a specific item's data).
**Action:** When memoizing list components, ensure parent components pass stable callback references using `useCallback`. Refactor callback signatures to accept identifying arguments (e.g., `id`, `title`) instead of closing over specific item data. If a stable callback needs to access frequently changing state, use `useRef` to maintain a stable reference to that state instead of adding it to the dependency array, avoiding stale closures while preserving memoization.
