## 2025-01-20 - Memoization of lists with callbacks
**Learning:** In large React lists where each item requires callbacks to access functionality from the parent view (like `onRemove`, `onToggleFavorite`), using inline arrow functions (e.g. `onRemove={() => handleRemove(item.id)}`) causes unnecessary re-renders of the child components because the function reference changes on every render. If we try to use `React.memo` on the child component, this still breaks memoization. Furthermore, attempting to use `React.memo` with a custom comparison function that ignores inline callbacks is an anti-pattern that leads to stale closures.
**Action:** Refactor child component callback props to accept identifiers (`id`, `title`) directly (e.g. `onRemove?(id: string): void`). Then use stable references to these callbacks created by `useCallback` in the parent component. Pass these stable references to the child components to allow `React.memo` to work properly and prevent unnecessary re-renders across the entire list. When memoizing the callbacks, if they depend on frequently changing state, maintain a stable reference to that state using `useRef` to prevent adding it to the `useCallback` dependency array.
