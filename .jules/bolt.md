## 2025-02-24 - Stable callbacks and React.memo in lists
**Learning:** In React components rendering lists (like `LibraryPage`, `DashboardPage` mapping over items into `BookCard`), passing inline callbacks effectively disables the memoization benefits of `React.memo` since a new callback instance is created on every render. This forces re-renders of all list items whenever the parent's state changes, leading to significant performance overhead and "stale closures" when using typical optimizations. When accessing frequently changing parent state (like the current `collection` inside a list item callback), simply putting the parent state in a `useCallback` dependency array also triggers re-renders.
**Action:** When memoizing list components, refactor child component callback signatures to accept identifying arguments (e.g., `id`, `title`) instead of closing over specific item data. Wrap the callback in `useCallback` in the parent. If the parent needs to access frequently changing state inside that stable callback without losing memoization benefits, store that parent state in a `useRef` and reference `ref.current` inside the `useCallback` instead of passing it to the dependency array.
