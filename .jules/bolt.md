## 2025-02-18 - Avoid stale closures by passing identifiers directly to child component callbacks
**Learning:** In React list views (like `LibraryPage`), defining inline arrow functions for item callbacks (e.g., `onRemove={() => remove(item.id)}`) creates new function references on every render. This defeats `React.memo` on child components (like `BookCard`), causing all items to re-render when the parent updates. However, using `React.memo` with custom comparison functions that ignore inline callbacks creates a stale closure problem, leading to outdated state inside the handler.
**Action:** Refactor child component props to accept identifying arguments (e.g., `id`, `title`) in callbacks (`onRemove?(id: string)`). In the parent, use `useCallback` to define stable handlers that expect these identifiers, then pass the stable references directly to the memoized child components (`onRemove={handleRemove}`).
