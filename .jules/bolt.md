## 2024-10-24 - Stable Callbacks in List Components
**Learning:** In the React frontend, when mapping over items to render list components (like `BookCard`), passing an inline arrow function that closes over item properties (like `work.id`) creates a new function reference on every re-render. This completely defeats `React.memo`, causing O(N) re-renders when list data changes or when parent components sort/filter items. Custom equality functions in `React.memo` that ignore inline callbacks can mask this issue but introduce dangerous stale closure bugs.
**Action:** When designing component APIs, prefer passing identifying arguments (like `id`) back up through stable callbacks (`onClick={(id) => ...}`) rather than generating closures per item. Always wrap list items in `React.memo` combined with `useCallback` on the parent to ensure efficient list rendering.
