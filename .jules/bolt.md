## 2024-10-26 - Prevent Stale Closures in Memoized List Components
**Learning:** When using React.memo on list items (like BookCard), passing inline arrow functions from parent components (e.g., `onClick={() => onRemove(work.id)}`) breaks memoization and causes all items to re-render when the parent updates. If the parent tries to fix this by using `useCallback` but the callback closes over the item data (e.g. `useCallback(() => remove(work.id), [work.id])`), it still results in a unique function per item, which is inefficient. Furthermore, passing an inline closure to an item in a mapped list and then memoizing the item requires the callback signature to accept identifying parameters.
**Action:** Always refactor child component callback props to pass necessary identifying information (like `id`) back to the parent. Then, in the parent list component, use a single `useCallback` that accepts these arguments, and optionally use `useRef` for rapidly changing external state (like the current collection) so the callback reference remains stable across renders without becoming stale.
