# Mochi Reader Reading Engines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать безопасные text/PDF и manga readers с точным автосохранением, закладками, историей, заметками и горячими клавишами.

**Architecture:** Rust нормализует book/manga content и выдаёт только валидированные ресурсы. React readers используют виртуализацию/колонки, небольшое окно ресурсов и независимые Zustand stores.

**Tech Stack:** Rust, quick-xml, zip, ammonia, pulldown-cmark, lopdf, unrar-rs, React, Zustand, pdfjs-dist, DOMPurify, Motion, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-30-mochi-reader-design.md`

## Global Constraints

- EPUB/HTML/FB2/Markdown content не выполняет JavaScript и проходит двойную sanitization.
- PDF active actions, вложения и embedded JavaScript не выполняются.
- CBZ/CBR/ZIP extraction применяет traversal/bomb limits.
- Прогресс сохраняется автоматически и flush-ится при navigation/close.
- Manga RTL меняет семантику next/previous, но не порядок данных в manifest.
- Все новые production-функции проходят RED → GREEN → REFACTOR.
